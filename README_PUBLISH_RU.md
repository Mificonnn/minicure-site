# MiniCure — сайт и публикация на minicure.ru

## Что внутри

- `index.html` — главная страница
- `features.html` — возможности
- `download.html` — загрузка DMG и инструкция
- `about.html` — информация о проекте и ограничения
- `assets/` — CSS, JavaScript, логотип и скриншоты
- `downloads/MiniCure.dmg` — DMG, переданный автором
- `CNAME` — пользовательский домен `minicure.ru`
- `.nojekyll` — отключает обработку Jekyll для статических файлов

Сайт статический: серверная часть и база данных не нужны.

## Важно про DMG перед публичным запуском

На странице загрузки намеренно размещено предупреждение. По ранее присланному скриншоту друга, предыдущая сборка показывала предупреждение macOS «damaged and can't be opened». Этот архив содержит предоставленный DMG (SHA-256: `2b0e8e5940976384423df583ce4e628d2aa742090930e622c07a6aa6a6afdfe4`), но его успешный запуск на другом Mac не подтверждён. Лучше исправить сборку, проверить её на отдельном Mac, а затем обновить `downloads/MiniCure.dmg` и SHA-256 в `download.html`.

## Бесплатная публикация через GitHub Pages

1. Войдите в GitHub и создайте **публичный** репозиторий, например `minicure-site` (GitHub Pages на бесплатном плане доступен для публичных репозиториев).
2. Загрузите содержимое этой папки в корень репозитория — не саму папку-обёртку и не ZIP-архив.
3. Откройте репозиторий → **Settings → Pages**.
4. В блоке **Build and deployment** выберите публикацию из ветки `main`, папка `/ (root)`, затем Save.
5. Сначала добавьте пользовательский домен в GitHub Pages: **Settings → Pages → Custom domain**, введите `minicure.ru`, нажмите Save. Файл `CNAME` уже включён в этот пакет.
6. В личном кабинете REG.RU откройте управление доменом `minicure.ru` → DNS / управление зоной. Добавьте A-записи:

   | Тип | Имя | Значение |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |

7. Чтобы работал `www.minicure.ru`, добавьте CNAME: имя `www`, значение — `<ВАШ_GITHUB_USERNAME>.github.io` (вместо плейсхолдера укажите имя пользователя/организации GitHub).
8. Если в DNS уже есть конфликтующие A/AAAA/CNAME записи для `@` или `www`, проверьте их перед заменой. Не добавляйте wildcard-записи `*`.
9. Подождите обновления DNS (иногда до 24 часов). После появления сайта откройте Settings → Pages и включите **Enforce HTTPS**, когда переключатель станет доступен.
10. Проверьте `https://minicure.ru`, страницы «Возможности», «Скачать», «О проекте» и кнопку DMG.

Официальные инструкции GitHub: https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site

Инструкция REG.RU по DNS: https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/kak-privyazat-domen-k-storonnemu-hostingu

## Как обновить DMG

1. Замените `downloads/MiniCure.dmg` новой проверенной сборкой.
2. Узнайте хеш: `shasum -a 256 downloads/MiniCure.dmg`.
3. Обновите в `download.html` размер, статус сборки и поле SHA-256.
4. Загрузите изменения в GitHub — Pages автоматически обновит сайт после публикации.

## Предупреждения

- Не публикуйте частные ключи, токены или персональные данные в репозитории.
- Сама регистрация домена не размещает сайт; его нужно отдельно опубликовать на хостинге.
- MiniCure описан как учебный проект; сайт специально не утверждает, что это сертифицированный антивирус или что в приложении есть обученная нейросеть.
